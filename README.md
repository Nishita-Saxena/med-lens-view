# MedLens Health Hub

MEDLENS — AI-POWERED CLINICAL INFORMATION INTELLIGENCE

ROLE

Act as a senior product architect, UX/UI designer, full-stack engineer, AI engineer, data architect, security engineer, and responsible-AI engineer.

Build a polished, production-oriented web application called MedLens.

Do not treat this as a simple AI chatbot.

MedLens is a structured medical-information organization and review system. Its primary purpose is to transform fragmented patient information and medical reports into a structured, traceable, understandable, and reviewable patient record.

The application must prioritize:

Accuracy

Traceability

Human verification

Privacy

Security

Accessibility

Reliability

Responsible AI

Clear separation between source information and AI-generated content

Do not invent medical facts, reference ranges, diagnoses, treatments, medications, or clinical recommendations.

1. PRODUCT VISION

Product Name

MedLens

Product Subtitle

AI-Powered Clinical Information Intelligence

Core Problem

Medical information is frequently fragmented across:

Patient history

Symptoms

Existing conditions

Allergies

Medications

Laboratory reports

Diagnostic reports

Previous medical records

Different dates and sources

This makes it difficult to efficiently organize, review, understand, and compare information.

Product Goal

Build an application that allows a user to:

Enter patient information.

Upload medical reports.

Extract relevant information from those reports.

Organize information into a structured patient record.

Preserve the original source and provenance of extracted information.

Interpret laboratory values only against reference ranges explicitly provided in the source report.

Identify low/normal/high status when the source range supports it.

Flag inconsistencies or conflicts.

Allow human review and correction.

Compare information across reports.

Generate a concise, patient-friendly summary.

Clearly distinguish factual source information from AI-generated interpretation.

Maintain a reviewable history of changes.

MedLens must assist with organizing and understanding medical information.

It must NOT function as a diagnostic or treatment system.

2. CRITICAL SAFETY BOUNDARY

This requirement is mandatory.

MedLens is an information organization and summarization system, NOT a medical diagnosis or treatment system.

The AI must NOT:

Diagnose diseases.

Provide definitive diagnoses.

Prescribe medications.

Recommend medication changes.

Recommend dosage changes.

Tell users to start, stop, or alter medication.

Generate treatment plans.

Replace professional medical judgment.

Present uncertain information as established medical fact.

Invent laboratory reference ranges.

Invent missing laboratory values.

Invent patient history.

Infer facts that are not supported by the source.

Convert an ambiguous result into a definitive medical conclusion.

When information is incomplete or ambiguous, explicitly indicate that it is incomplete or uncertain.

Use language such as:

"Not provided in the source."

"Unable to determine from the available information."

"This value was extracted from the uploaded report."

"The source report does not provide a reference range."

"This information requires verification."

"AI-generated summary; not a diagnosis."

Do not use alarmist language.

The application should encourage consultation with a qualified healthcare professional when appropriate without providing individualized treatment instructions.

11. REFERENCE RANGE RULE

This is one of the most important requirements.

MedLens must NEVER invent reference ranges.

If the source report provides:

Test: Hemoglobin
Value: 13.2
Unit: g/dL
Reference range: 12.0–16.0

Then MedLens may determine that the value falls within the stated range.

If the source report does NOT provide a reference range:

Display:

"Reference range not provided in source."

Do NOT use a generic internet reference range.

Do NOT silently substitute a database range.

Do NOT infer a range based on age, sex, location, or medical knowledge unless a future feature explicitly establishes a verified external reference source and clearly identifies it.

For the initial implementation, use only reference ranges explicitly present in the source report.

12. LABORATORY STATUS

When sufficient source information exists, calculate:

Low

Within stated range

High

The status must be derived from the source report's reference range.

If the value cannot reliably be compared:

Status:

"Unable to determine"

Examples:

Value = 8
Reference = 10–20
→ Low

Value = 15
Reference = 10–20
→ Within stated range

Value = 25
Reference = 10–20
→ High

If the value is qualitative rather than numeric:

Do not force it into Low/Normal/High.

Preserve the original reported result.

38. AI ARCHITECTURE

Do not ask one general-purpose AI prompt to perform all medical processing in an uncontrolled free-form response.

Never diagnose.
